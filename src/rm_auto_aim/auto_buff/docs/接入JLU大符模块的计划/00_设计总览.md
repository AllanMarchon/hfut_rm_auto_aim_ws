# 接入 JLU 大符模块设计总览

## 1. 目标与边界

目标：在不破坏现有装甲板链路的前提下，将 `tmp/jlu_vision_26/src/auto_buff` 能力接入当前 `gimbal_pipeline`，支持大符/小符的目标选择、云台规划与开火建议。

边界：
- 不直接迁移 JLU 的 iceoryx/xmake/quill 运行时。
- 以 ROS2 现有消息与节点体系为主。
- 默认保留原有装甲板行为不变。
- `tools/common_defs` 不整包迁移，仅迁移算法最小子集。

## 2. 核心演进路线

1. `robot_description` 内聚
- 收拢复用的“机器人状态语义 + 几何派生”能力。
- 消除各模块重复几何推导。

2. `robot_description` 双模式升级
- `YAW_PLANE`: 当前强先验，默认模式。
- `FULL_SE3`: 允许使用完整姿态（`center_pose` + `armors_offset.orientation`）。

3. `auto_buff` 适配接入
- 先完成 `auto_buff` ROS2 化（tracker 优先，detector 次之）。
- 新增适配器，将 buff 输出映射到 `TrackedRobot/TrackedRobots`。
- 新增 buff 专用选板策略与开火建议策略（不污染现有装甲板策略）。

## 3. 架构原则

- 语义收敛：状态语义/几何语义统一由 `robot_description` 提供。
- 策略解耦：`target_selector`/`fire_advice` 只消费几何结果，不重复实现几何。
- 风险隔离：buff 目标独立策略、独立开关、独立配置。
- 渐进上线：默认 `YAW_PLANE`，仅 buff 目标启用 `FULL_SE3`。
- 依赖收敛：优先用 `rm_interfaces/tf2/rclcpp` 替代 JLU 公共运行时依赖。

## 4. 交付物

- 设计与计划文档（本目录）。
- `robot_description` 内聚 API 与双模式实现。
- `auto_buff` 适配器。
- `auto_buff` ROS2 包化与依赖清理结果（去 iceoryx_deps）。
- buff 选板策略与 buff 开火建议链路。
- 配置、调试指标、回滚方案、验收脚本。
