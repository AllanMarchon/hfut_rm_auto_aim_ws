# 坐标系定义说明

## 世界坐标系（UKF/Tracker坐标系）

本项目使用**odom世界坐标系**作为统一坐标系，采用**右手坐标系**：

- **X轴**：水平向右
- **Y轴**：水平向前  
- **Z轴**：竖直向上（垂直于地面）

> **说明**：
>
> - 此坐标系与机器人传感器坐标系（相机坐标系）**可能不同**
> - XY平面为水平地面，Z轴垂直于地面
> - 假定机器人的中心轴（自旋轴）与世界坐标系的Z轴**平行**
> - 所有位置、速度、角度计算均在odom世界坐标系下进行
> - 装甲板观测数据从相机坐标系通过TF变换到odom坐标系

## 相机坐标系与坐标变换

### 相机坐标系定义

相机坐标系（camera_optical_frame）通常为：

- **X轴**：图像水平向右
- **Y轴**：图像竖直向下
- **Z轴**：相机光轴向前（指向场景）

### TF变换流程

装甲板检测器输出的装甲板位姿在相机坐标系中，需要通过TF树变换到odom世界坐标系：

```
camera_optical_frame → camera_link → gimbal → base_link → odom
```

变换由`tf_handler.py`的`transform_armor_to_observation`方法完成。

## Yaw角定义

### 坐标系约定

- **Yaw角零点**：相对于世界坐标系X轴正方向
- **Yaw角正方向**：从Z轴正方向向下看，**逆时针**为正（右手系）
- **角度范围**：归一化到 `[-π, π]`

### 1. 装甲板Yaw（armor_yaw）

**物理意义**：装甲板的朝向，定义为**机器人中心指向装甲板中心的径向方向**（外法向）

**计算方式**：

```
armor_yaw = center_yaw + panel_angle
```

其中：

- `center_yaw`：机器人中心的朝向角（相对于世界坐标系X轴）
- `panel_angle`：该装甲板相对于中心的角度偏移
  - Panel 0: 0°       (r1, lower层)
  - Panel 1: 90°      (r2, upper层)
  - Panel 2: 180°     (r1, lower层)
  - Panel 3: 270°     (r2, upper层)

**装甲板位置计算**（XY平面）：

```python
# armor_yaw = 中心指向装甲板的径向角度
armor_pos_x = center_x + radius * cos(armor_yaw)
armor_pos_y = center_y + radius * sin(armor_yaw)
```

**可视化示意**（俯视图，从Z轴正方向向下看）：

```
        Y (前)
        ↑
        |
Panel 1 • (r2, upper, yaw=90°)
        |
--------•--------→ X (右)
  Panel 0/2
  (r1, lower)
        |
Panel 3 • (r2, upper, yaw=270°)
```

### 2. 中心Yaw（center_yaw）

**物理意义**：机器人旋转中心的朝向角，即Panel 0的径向方向

**与armor_yaw的关系**：

```
center_yaw = armor_yaw - panel_angle
```

**备注**：由于机器人是4面对称结构，center_yaw具有180°对称性（center_yaw与center_yaw+π物理等价）

## 高度（Z坐标）定义

### 装甲板高度结构

装甲板在Z方向上有两个高度层级：

- **装甲板平均高度**：`z_mean`（UKF状态中的Z）
- **装甲板高度差**：`dza`（半高度差，即上下层之间一半的垂直距离）

**装甲板Z坐标计算**：

```python
# Upper层（Panel 1, 3）：更高
z_upper = z_mean + dza

# Lower层（Panel 0, 2）：更低
z_lower = z_mean - dza
```

**物理意义**：

- `z_mean`：装甲板平面的中心高度
- `2 * dza`：上下两层装甲板的垂直距离
- Panel配置：
  - Panel 0, 2（偶数，r1）→ Lower层 → `z = z_mean - dza`
  - Panel 1, 3（奇数，r2）→ Upper层 → `z = z_mean + dza`

## 观测数据约定

从检测算法得到的观测数据在相机坐标系中，经过TF变换和yaw转换后：

- `x, y, z`：装甲板中心在odom世界坐标系下的位置
- `yaw`：装甲板的**径向方向**（机器人中心指向装甲板），**非法向**

**关键约定**：

- ✅ 装甲板检测器输出的orientation表示装甲板**法向**（Z轴指向观察者）
- ✅ `msg_converter.py`中自动将法向yaw转换为径向yaw（加π）
- ✅ `obs.yaw` = armor_yaw（径向方向：中心→装甲板）
- ✅ `obs.x, obs.y, obs.z` = 装甲板位置在odom坐标系中的坐标

## UKF状态向量

### 状态定义（11维 - CV模型）

```python
[x, vx, y, vy, z, vz, delta, delta_rate, r1, r2, dza]
```

| 索引 | 变量 | 含义 | 单位 |
|------|------|------|------|
| 0 | x | 中心X位置 | m |
| 1 | vx | 中心X速度 | m/s |
| 2 | y | 中心Y位置 | m |
| 3 | vy | 中心Y速度 | m/s |
| 4 | z | 装甲板平均高度 | m |
| 5 | vz | Z速度 | m/s |
| 6 | delta | 连续角度 | rad |
| 7 | delta_rate | 角速度 | rad/s |
| 8 | r1 | 偶数Panel半径 | m |
| 9 | r2 | 奇数Panel半径 | m |
| 10 | dza | 装甲板高度差 | m |

### Yaw分解表示

为处理180°对称性，采用**分解表示**：

```
center_yaw = k * π + delta
```

其中：

- `k ∈ {0, 1}`：离散模态（0或π）
- `delta ∈ [-π/2, π/2]`：连续小角度偏移

**优势**：

- 状态空间在 `[-π/2, π/2]` 连续更新
- 通过后验概率选择最优k
- 避免角度跳变和不连续性

## 数据流转换

### 1. 观测输入 → UKF更新（单观测）

```python
# 输入：装甲板观测（相机坐标系）
armor_msg = Armor(...)  # 来自装甲板检测器

# TF变换：相机坐标系 → odom坐标系
obs = tf_handler.transform_armor_to_observation(armor_msg, source_frame, timestamp)
# obs.yaw 已自动从法向转换为径向（msg_converter中加π）

# Panel关联：从armor_yaw推断panel_id
panel_id = determine_panel(armor_yaw, center_yaw_pred)
panel_angle = panel_id * (π / 2)

# 转换为center_yaw用于UKF更新
center_yaw_obs = normalize_angle(armor_yaw - panel_angle)

# UKF观测向量（内部使用center_yaw）
z_obs = [x_armor, y_armor, z_armor, center_yaw_obs]
```

### 2. UKF预测 → 观测空间

```python
# UKF状态中的center_yaw
center_yaw = compose_yaw(k, delta)  # k*π + delta

# 预测装甲板观测（给定panel_angle）
armor_yaw_pred = normalize_angle(center_yaw + panel_angle)

# 装甲板位置
armor_x_pred = center_x + radius * cos(armor_yaw_pred)
armor_y_pred = center_y + radius * sin(armor_yaw_pred)

# 装甲板高度
if panel_id % 2 == 0:  # Lower层
    armor_z_pred = z_mean - dza
else:  # Upper层
    armor_z_pred = z_mean + dza

# 预测观测（注意：内部使用center_yaw）
z_pred = [armor_x_pred, armor_y_pred, armor_z_pred, center_yaw]
```

### 3. 双观测几何更新

双观测时，利用两个装甲板的位置和yaw直接计算机器人中心：

```python
# 装甲板yaw指向外（中心→装甲板），需反向求中心
yaw1_to_center = normalize_angle(armor_yaw_1 + π)
yaw2_to_center = normalize_angle(armor_yaw_2 + π)

# 两条射线求交点
# Line 1: armor_pos_1 + t1 * [cos(yaw1_to_center), sin(yaw1_to_center)]
# Line 2: armor_pos_2 + t2 * [cos(yaw2_to_center), sin(yaw2_to_center)]

# 求解中心位置和半径
center_pos = solve_intersection(...)
r1_est = distance(center_pos, armor_pos_1)
r2_est = distance(center_pos, armor_pos_2)
```

## 实现关键点总结

1. **装甲板检测器输出**（`armor_detector`）：
   - `armor.pose.position`: 装甲板中心在相机坐标系中的位置
   - `armor.pose.orientation`: 装甲板法向（Z轴指向观察者）

2. **坐标系转换**（`tf_handler.py::transform_armor_to_observation`）：

   ```python
   # 通过TF树将装甲板从相机坐标系变换到odom坐标系
   transformed_pose = tf_buffer.lookup_transform(odom, camera, ...)
   # 调用pose_to_observation自动将法向yaw转换为径向yaw
   obs = pose_to_observation(transformed_pose, timestamp)
   ```

3. **Yaw转换**（`msg_converter.py::pose_to_observation`）：

   ```python
   # 提取法向yaw
   yaw_normal = quaternion_to_yaw(pose.orientation)
   # 转换为径向yaw（中心指向装甲板）
   yaw_radial = yaw_normal + π
   return ObservationData(..., yaw=yaw_radial)
   ```

### 🔧 注意事项

1. **装甲板检测器输出的yaw含义**：
   - 装甲板检测器输出的`orientation`四元数表示**装甲板法向**（Z轴指向观察者）
   - 经过`msg_converter.py`转换后得到**径向yaw**（中心指向装甲板）
   - 转换公式：`yaw_radial = yaw_normal + π`

2. **坐标系统一**：
   - 所有观测、跟踪、预测均在**odom世界坐标系**中进行
   - odom坐标系定义：X-右，Y-前，Z-上（右手系）
   - 装甲板观测自动从相机坐标系通过TF变换到odom

3. **观测模型返回值**：
   - `_observation_model`返回`center_yaw`（非`armor_yaw`）
   - 更新时将`obs.yaw`（armor_yaw）转换为`center_yaw`
   - 保持内部一致性

4. **Panel关联**：
   - 输入：`armor_yaw`（装甲板观测的yaw，已经是径向）
   - 输出：`panel_id`和`center_yaw`
   - 关系：`center_yaw = armor_yaw - panel_angle`

5. **180°对称性**：
   - `center_yaw`与`center_yaw + π`物理等价
   - Yaw误差计算需考虑对称性
   - 使用`compute_yaw_error_symmetric`函数

6. **角度归一化**：
   - 所有角度计算后使用`normalize_angle`
   - 角度残差使用`delta_angle_diff`或`normalize_angle`
   - 确保在`[-π, π]`范围内

## 与旧版虚拟坐标系的区别

**旧版设计**（已废弃）：

- 引入虚拟坐标系（virtual_camera_frame），消除相机roll/pitch
- 在虚拟坐标系中进行跟踪，输出时再转换回odom
- 增加了复杂性和转换误差

**新版设计**（当前）：

- 直接在odom世界坐标系中进行跟踪
- 简化了实现，减少了坐标转换次数
- 假设odom坐标系的Z轴已经与重力方向对齐
- 如果相机有较大的roll/pitch，应在TF树中正确配置相机姿态
