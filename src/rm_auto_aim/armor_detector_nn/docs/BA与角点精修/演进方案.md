# armor_detector_nn：BA 与角点精修无歧义演进方案

## 1. 文档目的与范围

本方案用于指导 `src/rm_auto_aim/armor_detector_nn` 的位姿估计链路演进，目标是分阶段实现：

1. 主链路实时兜底（IPPE PnP + 单帧 yaw BA）
2. Tracker 策略化（先内置 IoU）
3. ROI 角点精修（可开关）
4. per-track 滑窗 BA（作为单帧 BA 的可配置替换模式）
5. 异步整合（增强链路异步，主链路不阻塞）

本方案只覆盖 `armor_detector_nn` 包内改造；外部包只通过适配器接入，不直接侵入其内部实现。

---

## 2. 强约束（必须遵守）

1. 每帧必须可输出：增强失败不能阻塞主链路。
2. 所有增强模块必须可开关：`tracker`、`corner_refine`、`pose_refine`、`async`。
3. 所有增强模块必须有失败回退：
   - `sliding_ba -> single_yaw_ba -> pnp`
   - `corner_refine_failed -> raw_corners`
4. 任何阶段引入新模块后，默认配置必须保持与当前行为接近（先保守）。
5. 任何跨模块通信以 `track_id` 为唯一轨迹键，不使用隐式索引。

---

## 3. 总体架构（最终形态）

```text
image -> detect -> tracker(assign track_id)
      -> main pose path (PnP + SingleYawBA) -> immediate publish
      -> enhancement path (corner refine + SlidingBA)
           -> quality gate -> optional overwrite publish candidate
      -> async integration (phase6): main path waits max_wait_ms then fallback
```

输出优先级：

1. `SW_BA_VALID`
2. `SINGLE_BA_VALID`
3. `PNP_VALID`
4. `LOST`

---

## 4. 分阶段实施计划

## Phase 1：主链路兜底（IPPE + 单帧 yaw BA）

### 4.1 目标

在现有同步链路上，实现稳定的位姿兜底：

1. `IPPE PnP` 给出 `tvec/rvec`
2. 单帧 `yaw` 优化（固定 `tvec`，固定 pitch/roll）
3. BA 失败自动回退 PnP

### 4.2 文件改动

1. `include/armor_detector_nn/core/detector_config.hpp`
2. `include/armor_detector_nn/core/armor_pose_estimator_adapter.hpp`
3. `src/core/armor_pose_estimator_adapter.cpp`
4. 新增：`include/armor_detector_nn/core/pose_refiner.hpp`
5. 新增：`src/core/single_yaw_ba_refiner.cpp`

### 4.3 配置项（新增）

放入 `pose` 命名空间：

1. `pose.refiner.mode`: `none|single_yaw|sliding_window`（Phase1 默认 `single_yaw`）
2. `pose.single_yaw.max_iterations`（默认 15）
3. `pose.single_yaw.huber_delta`（默认 3.0）
4. `pose.single_yaw.pitch_deg_default`（默认 15.0）
5. `pose.single_yaw.roll_deg_default`（默认 0.0）
6. `pose.single_yaw.outpost_pitch_sign`（默认 true）

### 4.4 行为定义

1. 若 `PnP` 失败：返回 `PoseEstimate.valid=false`。
2. 若 `PnP` 成功且 `single_yaw` 启用：尝试优化 `yaw`。
3. 若优化失败、NaN、或结果超限：丢弃优化结果，保留 PnP。
4. `PoseEstimate` 中新增：`mode`、`quality_score`、`reproj_error_raw`、`reproj_error_refined`。

### 4.5 验收标准

1. 不降低当前帧率超过 10%。
2. 姿态输出连续，无新增明显跳变。
3. BA 失败不影响发布频率。

---

## Phase 2：Tracker 策略化（先内置 IoU）

### 5.1 目标

将 `track_id` 建立为统一主键，为后续 per-track 窗口提供基础。

### 5.2 接口与类

新增：

1. `include/armor_detector_nn/core/tracker/tracker_types.hpp`
2. `include/armor_detector_nn/core/tracker/itracker_strategy.hpp`
3. `include/armor_detector_nn/core/tracker/internal_iou_tracker_strategy.hpp`
4. `src/core/tracker/internal_iou_tracker_strategy.cpp`
5. `include/armor_detector_nn/core/tracker/tracker_factory.hpp`
6. `src/core/tracker/tracker_factory.cpp`

### 5.3 数据结构定义

在 `ArmorDetection` 增加字段：

1. `int track_id{-1}`
2. `int track_age{0}`
3. `int track_hits{0}`

新增内部结构：

1. `TrackedDetection { ArmorDetection det; int track_id; bool matched; }`
2. `TrackState { int id; cv::Rect2f bbox; cv::Point2f center; int age; int hits; int missed; rclcpp::Time last_stamp; }`

### 5.4 配置项

放入 `tracker` 命名空间：

1. `tracker.strategy`: `internal_iou|muit_sort`（Phase2 默认 `internal_iou`）
2. `tracker.iou_threshold`（默认 0.30）
3. `tracker.max_missed`（默认 15）
4. `tracker.min_hits`（默认 2）
5. `tracker.max_center_dist_px`（默认 120）

### 5.5 关联规则（无歧义）

1. 先按上一帧轨迹预测框与当前检测构造代价矩阵。
2. 代价定义：`cost = 1 - IoU`。
3. 使用匈牙利匹配。
4. 若 `IoU < threshold` 或 `center_dist > max_center_dist_px`，匹配作废。
5. 未匹配检测创建新轨迹。
6. 未匹配轨迹 `missed++`，超过 `max_missed` 删除。
7. 仅当 `hits >= min_hits` 时标记 confirmed（可供后续增强链路优先）。

### 5.6 验收标准

1. 每个检测都稳定携带 `track_id`（允许短时 -1）。
2. 遮挡后恢复时 ID 切换率可接受（记录指标）。
3. 不引入显著延迟。

---

## Phase 3：ROI 角点精修（可开关）

### 6.1 目标

仅在局部 ROI 内对角点做传统精修，提高 PnP 几何稳定性。

### 6.2 接口与类

新增：

1. `include/armor_detector_nn/core/corner_refine/icorner_refiner.hpp`
2. `include/armor_detector_nn/core/corner_refine/roi_pca_corner_refiner.hpp`
3. `src/core/corner_refine/roi_pca_corner_refiner.cpp`

### 6.3 I/O 定义

输入：

1. 原图 `cv::Mat frame`
2. `ArmorDetection`（含 bbox + raw keypoints + track_id）

输出：

1. `RefineResult`
2. `bool ok`
3. `std::array<cv::Point2f,4> refined_keypoints`
4. `double refine_quality`
5. `double elapsed_ms`
6. `RefineFailReason reason`

### 6.4 失败回退条件

命中任一条件即 `ok=false`：

1. ROI 尺寸过小或过大
2. 亮区点数不足
3. PCA 主方向不稳定
4. 几何约束不通过（长宽比/面积/凸性）
5. 耗时超过 `time_budget_ms`

并严格回退为原始 keypoints。

### 6.5 配置项

1. `corner_refine.enabled`（默认 false）
2. `corner_refine.apply_on_confirmed_only`（默认 true）
3. `corner_refine.max_targets_per_frame`（默认 1）
4. `corner_refine.time_budget_ms`（默认 2.0）
5. `corner_refine.roi_expand_ratio`（默认 1.2）
6. `corner_refine.min_bright_points`（默认 30）

### 6.6 验收标准

1. 开关关闭时行为与 Phase2 一致。
2. 开关开启后平均重投影误差下降。
3. 耗时受控，超时比例可统计。

---

## Phase 4：per-track 滑窗 BA（可配置替换单帧 BA）

### 7.1 目标

将 `sliding_window_ba` 作为 `single_yaw_ba` 的可配置替换模式。

### 7.2 接口与类

新增：

1. `include/armor_detector_nn/core/pose_refine/ipose_refiner_strategy.hpp`
2. `include/armor_detector_nn/core/pose_refine/single_yaw_refiner_strategy.hpp`
3. `include/armor_detector_nn/core/pose_refine/sliding_window_refiner_strategy.hpp`
4. `src/core/pose_refine/sliding_window_refiner_strategy.cpp`
5. `include/armor_detector_nn/core/pose_refine/sliding_window_state.hpp`

### 7.3 窗口数据结构

`TrackWindowFrame`：

1. `rclcpp::Time stamp`
2. `int track_id`
3. `std::array<cv::Point2f,4> corners`
4. `std::array<float,4> corner_conf`
5. `Eigen::Vector3d t_init`
6. `double yaw_init`
7. `std::string armor_type`
8. `std::string armor_number`

每个 `track_id` 对应独立窗口容器。

### 7.4 配置项

1. `pose.refiner.mode=single_yaw|sliding_window`
2. `pose.sliding.window_size`（默认 8）
3. `pose.sliding.min_frames`（默认 4）
4. `pose.sliding.max_time_span_ms`（默认 300）
5. `pose.sliding.max_opt_iters`（默认 20）

### 7.5 质量门控阈值

1. `pose.gate.max_reproj_error`（默认 3.0 px）
2. `pose.gate.max_pose_delta_m`（默认 0.20 m）
3. `pose.gate.max_yaw_delta_deg`（默认 20 deg）
4. `pose.gate.require_finite`（默认 true）

### 7.6 回退规则

1. `sliding` 优化失败 -> 回退 `single_yaw`
2. `single_yaw` 失败 -> 回退 `pnp`
3. 门控不通过 -> 同上回退链

### 7.7 验收标准

1. 慢速和中速目标下抖动下降。
2. 高速/遮挡场景下仍可回退保证实时输出。

---

## Phase 5：muit_obj_tracker::SortTracker 适配器

### 8.1 目标

在不改主流程的前提下，允许从内置 IoU tracker 切换到外部 `muit_sort`。

### 8.2 适配器类

新增：

1. `include/armor_detector_nn/core/tracker/muit_sort_tracker_strategy.hpp`
2. `src/core/tracker/muit_sort_tracker_strategy.cpp`

### 8.3 映射定义（无歧义）

`ArmorDetection -> muit_obj_tracker::Detection`：

1. `bbox`：`Rect2f` 转 `Rect`（四舍五入）
2. `confidence`：直接映射
3. `corners`：复制 4 点
4. `id`：输入检测索引（仅帧内临时）

`TrackResult -> ArmorDetection.track_id`：

1. 依据匹配后的 `bbox IoU` 反查当前帧检测
2. 成功映射后写入 `track_id`
3. 未映射检测保留 `-1`

### 8.4 构建与依赖

1. `armor_detector_nn/CMakeLists.txt` 增加可选开关：`BUILD_MUIT_SORT_TRACKER`
2. 开启时链接 `muit_obj_tracker` 及其传递依赖
3. 默认关闭，避免依赖膨胀影响基础部署

---

## Phase 6：异步整合

### 9.1 目标

主链路实时发布，增强链路异步结果可用时覆盖；超时立即降级。

### 9.2 线程与队列

1. `LatestTaskQueue`：容量逻辑为 1，写入覆盖旧任务
2. Worker 单线程（首版）
3. 主线程等待 `max_wait_ms`，超时返回 fallback

### 9.3 任务结构

`EstimationTask`：

1. `frame_id`
2. `stamp`
3. `track_id`
4. `bbox`
5. `raw_keypoints`
6. `raw_pose_candidate`（主链路结果）
7. `image_ref`（只读引用或浅拷贝策略）

### 9.4 结果结构

`EnhanceResult`：

1. `frame_id`
2. `track_id`
3. `PoseEstimate estimate`
4. `bool quality_ok`
5. `double elapsed_ms`

### 9.5 参数

1. `async.enabled`（默认 false）
2. `async.max_wait_ms`（默认 2.0）
3. `async.drop_if_busy`（默认 true）

### 9.6 一致性规则

1. 只接受 `frame_id` 和 `track_id` 均匹配的异步结果
2. 结果过期（超过 `max_observation_age_ms`）直接丢弃

---

## 10. 统一状态机定义

`enum class EstimateMode`：

1. `LOST`
2. `PNP_VALID`
3. `SINGLE_BA_VALID`
4. `SW_BA_VALID`

状态迁移：

1. `LOST -> PNP_VALID`：PnP 成功
2. `PNP_VALID -> SINGLE_BA_VALID`：single BA 成功且门控通过
3. `SINGLE_BA_VALID -> SW_BA_VALID`：sliding BA 成功且门控通过
4. 任意状态 -> 低一级状态：当前增强失败或门控失败
5. 任意状态 -> LOST：PnP 失败

## 12. 配置模板（建议首版）

```yaml
pose:
  pnp_method: ippe
  refiner:
    mode: single_yaw
  single_yaw:
    max_iterations: 15
    huber_delta: 3.0
    pitch_deg_default: 15.0
    roll_deg_default: 0.0
  sliding:
    window_size: 8
    min_frames: 4
    max_time_span_ms: 300
    max_opt_iters: 20
  gate:
    max_reproj_error: 3.0
    max_pose_delta_m: 0.2
    max_yaw_delta_deg: 20.0
    require_finite: true

tracker:
  strategy: internal_iou
  iou_threshold: 0.30
  max_missed: 15
  min_hits: 2
  max_center_dist_px: 120

corner_refine:
  enabled: false
  apply_on_confirmed_only: true
  max_targets_per_frame: 1
  time_budget_ms: 2.0
  roi_expand_ratio: 1.2
  min_bright_points: 30

async:
  enabled: false
  max_wait_ms: 2.0
  drop_if_busy: true
```

## 14. 非目标（当前阶段不做）

1. 不在本阶段引入多线程并行优化器池。
2. 不在本阶段引入 ReID/外观特征关联。
3. 不在本阶段引入端到端学习式 pose refine。
