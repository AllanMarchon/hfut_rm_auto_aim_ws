# pybind11 KF 参数优化：实现大纲与计划

## 1. 背景与目标

当前 `gimbal_pipeline` 的滤波与关联链路已经具备较完善的在线能力，但参数调整主要依赖手工经验。为了提升调参效率与跨场景稳定性，计划引入 `pybind11` 包装关键滤波器接口，在 Python 侧进行离线重放与自动优化，最终回写到 ROS 参数。

本方案聚焦两条主链路：
- `Norm4ArmorTracker`（4装甲常规目标）
- `OutpostTrackerV2`（前哨站结构化/歧义双模式）

总体目标：
1. 建立可重复的离线评估闭环（重放 -> 评估 -> 优化 -> 验证）。
2. 找到比人工默认值更稳健的一组参数初值（不是单场景最优，而是跨场景可用）。
3. 最小化对线上主流程的侵入，优先以离线工具链落地。

---

## 2. 范围界定

### 2.1 In Scope
- 基于 `pybind11` 暴露 UKF/IMM 相关可调参数与必要状态读写接口。
- 使用现有 `PredictionLogger` 输出日志作为离线观测数据源。
- 建立分目标类型（norm4/outpost）的评估指标与目标函数。
- 使用 Python 优化器（如 `scipy.optimize`）进行参数搜索。
- 产出参数建议与配置回写模板（YAML/参数段）。

### 2.2 Out of Scope
- 不改动在线节点架构（仍由 C++ 线上执行）。
- 不在第一阶段引入端到端神经网络替代滤波器。
- 不做跨包大重构（先在 `gimbal_pipeline` 内闭环）。

---

## 3. 现状与可行性结论

### 3.1 接口可包装性
现有滤波器接口已具备良好包装基础：
- 可读写状态与协方差：`x() / P()`
- 状态索引查询：`state_idx()`
- 诊断信息：`last_innov_xyz() / last_innov_yaw() / last_nis() / last_update_type()`

这意味着 Python 侧可以：
- 按帧重放观测；
- 读取每步误差与创新统计；
- 对参数进行批量试验。

### 3.2 数据链路一致性
观测数据经过 TF 转换到 `target_frame`（默认 `odom`）后进入 tracker 与 logger，语义一致，适合离线重放。

注意事项：CSV 当前未显式记录 `frame_id`，应在实施阶段补充元信息列，避免后处理误用坐标系。

## 4. 目标参数分层

### 4.1 第一优先级（建议先优化）
- `ukf.obs_noise_pos`
- `ukf.obs_noise_yaw`
- `motion.cv_process_noise_vel`
- `motion.ca_process_noise_acc`
- `motion.process_noise_r`
- `motion.process_noise_dz`
- `spin.spin_process_noise_delta_rate`
- `spin.spin_process_noise_delta_acc`

### 4.2 第二优先级（模式/关联稳定性）
- outpost: `outpost.softmax_temperature`, `binding_min_candidate_prob`, `binding_min_candidate_margin`
- norm4: `tracker.degraded_*`, `jump_binding_*`, `panel_mismatch.*`

### 4.3 固定不动（第一阶段）
- 状态维度结构与模型拓扑（CV/CA/Singer 组合关系）
- 核心状态机拓扑（仅调阈值，不改状态机定义）

---

## 5. 离线评估目标设计

采用多目标加权，防止“仅误差最小但行为不稳定”。

### 5.1 主目标（精度）
- `L_pos`: N-step（50/100/150ms）中心位置误差（RMSE）
- `L_yaw`: N-step yaw 误差（角度 wrap 后 RMSE）

### 5.2 稳定性目标
- `L_nis`: NIS 超阈比例（按 update_type 分组）
- `L_innov`: 创新向量范数 P95/P99
- `L_cov`: 协方差异常惩罚（过大/过小）

### 5.3 语义一致性目标（重点针对 outpost/norm4）
- `L_mode_switch`: 模式抖动惩罚（频繁 structured/ambiguous 切换）
- `L_bind_conflict`: 低 margin、高冲突、错误切换惩罚
- `L_degraded`: `degraded_single_obs_mode` 过长占比惩罚（norm4）

### 5.4 综合目标
\[
L = w_1 L_{pos} + w_2 L_{yaw} + w_3 L_{nis} + w_4 L_{innov} + w_5 L_{mode\_switch} + w_6 L_{bind\_conflict} + w_7 L_{degraded}
\]

建议初值：
- `w1=0.35, w2=0.20, w3=0.15, w4=0.10, w5=0.10, w6=0.07, w7=0.03`
- 后续按业务偏好（命中稳定 vs 快速响应）微调。

## 6. 技术方案

### 6.1 C++ 侧（pybind11 模块）
新增离线绑定模块（建议独立 target，避免污染主节点）：
- 暴露类型：
  - `ObservationData`
  - `UnifiedConfig`（只暴露优化所需字段）
  - `DualRadiusSpinUKF` / `OutpostSpinUKF`（优先）
- 暴露方法：
  - `initialize/predict/update`
  - `x/P/state_idx`
  - `last_nis/last_innov_xyz/last_update_type`

### 6.2 Python 侧（优化脚本）
- 数据层：读取 `PredictionLogger` 生成的 CSV。
- 回放层：按 `robot_id` 和时间序列喂入观测。
- 评估层：计算各项损失并返回总目标。
- 优化层：
  - 第一阶段：随机搜索 + 局部 Nelder-Mead
  - 第二阶段：CMA-ES 或贝叶斯优化（可选）

### 6.3 结果回写
- 输出：`best_params.json` + `ros2_params_patch.yaml`
- 附带：按场景分组的指标报告（总分与单项分）。

## 7. 实施计划（里程碑）

### M1：离线闭环打通（2~3 天）
- 新建 pybind11 模块，最小暴露 UKF 回放接口。
- 跑通单日志文件的逐帧重放。
- 产出基础误差与 NIS 报表。

交付物：
- `pybind` 模块可 import
- `replay_eval.py` 可运行

### M2：目标函数与自动优化（2~4 天）
- 完成多目标损失函数。
- 加入参数边界、非法值保护、早停策略。
- 输出首版优化参数。

交付物：
- `optimize_kf_params.py`
- `best_params.json`

### M3：多场景验证与参数固化（2~3 天）
- 按目标类型与场景分桶验证（近/中/远，快转/慢转，单/双观测）。
- 生成统一参数建议与场景特化参数建议。
- 回写配置并回归测试。

交付物：
- 验证报告（markdown）
- 参数补丁文件

### M4：工程化收尾（1~2 天）
- 增加日志元信息（frame/timestamp source/version）。
- 脚本 CLI 化，支持批量日志目录。
- 文档完善与使用说明。

交付物：
- 使用手册
- 一键批评估命令

## 8. 风险与对策

1. 过拟合单日志
- 对策：多场景交叉验证；按场景加权平均分，不看单一最优。

2. 坐标系误用导致指标失真
- 对策：日志写入 `target_frame` 元信息；评估脚本强校验。

3. 优化耗时过长
- 对策：两阶段优化（粗搜+精搜）；先优化高敏感参数子集。

4. 离线最优在线退化
- 对策：保留 conservative baseline；A/B 灰度切换；加入稳定性惩罚项。

---

## 9. 验收标准

满足以下条件可认为方案成功：
1. 可在固定日志集上稳定复现优化结果（重复运行方差可接受）。
2. 相对基线参数，综合目标 `L` 降低 >= 10%。
3. 关键单项不退化：
   - 模式抖动不上升；
   - NIS 极端离群比例不升高；
   - 轨迹连续性无明显变差。
4. 参数回写后，在线回放/仿真行为与离线趋势一致。

---

## 10. 下一步建议

1. 先做 M1 最小闭环，优先验证“可重放 + 指标可算”。
2. 同步补齐 logger 元信息字段（至少 `target_frame`）。
3. 第一批仅优化 6~8 个高敏参数，快速拿到可比较结果。
