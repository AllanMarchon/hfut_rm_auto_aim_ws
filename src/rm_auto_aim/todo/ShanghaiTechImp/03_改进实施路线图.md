# 改进实施路线图

> 基于上海科技大学2026技术方案对比分析，按优先级排列的具体改进任务

## P0: YPD 球坐标观测噪声建模

**目标**：将 R 矩阵从"对角 XYZ 固定噪声"升级为"YPD 球坐标动态噪声"

**实现审计结论**：
- 可以引入，且适合作为当前主链路的优先改动
- 原因：单观测 `R` 构造局部集中在 `dual_radius_spin_ukf.cpp`，观测接口仍是 `z=[x,y,z,yaw]`
- 不需要改状态维度，不需要改 `TrackerManager` 与上下游消息接口
- 与现有 `height_confidence / position_confidence` 缩放、innovation gating 兼容
- 双观测 `R_geo` 可以保持不动，因此改动边界清晰

**本轮实施范围（统一口径）**：
- 仅修改 `src/rm_auto_aim/gimbal_pipeline` 包
- 先不修改旧的 `src/rm_auto_aim/max_entropy_tracker` 独立实现
- 先不修改 `rm_bringup/config/<robot>/gimbal_pipeline.yaml`
- 因此本轮目标是“完成包内代码与默认参数设计”，不是“默认 bringup 启动立即生效”

**涉及文件（本轮仅限 gimbal_pipeline 包）**：
- [gimbal_pipeline/include/max_entropy_tracker/core/config.hpp](../../../gimbal_pipeline/include/max_entropy_tracker/core/config.hpp) — 新增 `UKFParameters` 成员
- [gimbal_pipeline/src/gimbal_pipeline_node.cpp](../../../gimbal_pipeline/src/gimbal_pipeline_node.cpp) — 新增参数声明与读取
- [gimbal_pipeline/src/max_entropy_tracker/filters/dual_radius_spin_ukf.cpp](../../../gimbal_pipeline/src/max_entropy_tracker/filters/dual_radius_spin_ukf.cpp) — 修改单观测 R 矩阵构造逻辑
- [gimbal_pipeline/config/gimbal_pipeline.yaml](../../../gimbal_pipeline/config/gimbal_pipeline.yaml) — 包默认参数

**具体步骤**：

1. 在 `UKFParameters` 中新增 3 个参数：
   - `ypd_sigma_azi` (默认 0.063) — 方位角噪声 std (rad)
   - `ypd_sigma_ele` (默认 0.063) — 俯仰角噪声 std (rad)
   - `ypd_sigma_dist_coeff` (默认 0.10) — 距离噪声系数

2. 在 `dual_radius_spin_ukf.cpp` 单观测更新处：
   - 从观测/预测值计算当前方位角、俯仰角、距离
   - 构建 4×4 雅可比 J = ∂(XYZ,yaw)/∂(azi,ele,dist,yaw)
   - R = J × diag(σ²) × J^T + 置信度缩放

3. 保留现有 `obs_noise_pos` 作为 fallback（当 `ypd_sigma_azi <= 0` 时回退到旧逻辑）

4. 双观测的 R_geo 暂不改造（几何观测模型本身已包含距离相关项）
5. 本轮只修改包默认参数：
   - 改 `gimbal_pipeline/config/gimbal_pipeline.yaml`
   - 不同步 `rm_bringup/config/<robot>/gimbal_pipeline.yaml`
   - 后续若需要接入 `bringup_pipeline.launch.py` 默认链路，再做第二阶段参数覆盖同步

**验证方法**：
- 打印改造前后 R 矩阵的对角线值，确认在不同距离下合理
- 确认 R 的非对角项（X-Y 协方差）非零且有物理意义
- 跑 bag 回放对比跟踪轨迹的平滑度

## P1: 启用马氏距离门控

**目标**：激活已有的 innovation gating，剔除异常观测

**本轮实施范围（统一口径）**：
- 仅修改 `src/rm_auto_aim/gimbal_pipeline` 包
- 不修改旧的 `src/rm_auto_aim/max_entropy_tracker`
- 不修改 `rm_bringup/config/<robot>/gimbal_pipeline.yaml`

**涉及文件**：
- [gimbal_pipeline/include/max_entropy_tracker/core/config.hpp](../../../gimbal_pipeline/include/max_entropy_tracker/core/config.hpp)
- [gimbal_pipeline/include/max_entropy_tracker/filters/dual_radius_spin_ukf.hpp](../../../gimbal_pipeline/include/max_entropy_tracker/filters/dual_radius_spin_ukf.hpp)
- [gimbal_pipeline/src/gimbal_pipeline_node.cpp](../../../gimbal_pipeline/src/gimbal_pipeline_node.cpp)
- [gimbal_pipeline/src/max_entropy_tracker/filters/dual_radius_spin_ukf.cpp](../../../gimbal_pipeline/src/max_entropy_tracker/filters/dual_radius_spin_ukf.cpp)
- [gimbal_pipeline/src/max_entropy_tracker/trackers/adaptive_armor_tracker.cpp](../../../gimbal_pipeline/src/max_entropy_tracker/trackers/adaptive_armor_tracker.cpp)
- [gimbal_pipeline/config/gimbal_pipeline.yaml](../../../gimbal_pipeline/config/gimbal_pipeline.yaml)

**具体步骤**：

1. 在包默认参数中启用 `ukf.enable_innovation_gating: true`
   - 本轮不直接修改分车型 `rm_bringup` 覆盖 YAML
   - 若需在主启动链路按车型灰度上线，后续再单独同步覆盖参数

2. 调整 `ukf.innovation_gate_chi2_threshold`：
   - 初始值建议 `5.02` (χ²(1) 97.5%)
   - 稳定后可根据实际 NIS 分布回调

3. 增加调试日志：记录被门控拒绝的观测比例（建议目标 2-8%）
4. 修正状态机联动：
   - 当前 gate reject 不会自然驱动 `TEMP_LOST`
   - 建议增加 reject streak，再决定是否触发 `handle_observation_loss()`

**依赖**：建议在 P0 完成后启用（门控效果依赖准确的 R 矩阵）

**验证方法**：
- 统计拒绝率是否在合理范围
- 确认连续多帧被拒绝时跟踪状态机正确转入 TEMP_LOST

## P2: Q 矩阵参数对标调整

**目标**：根据目标兵种机动能力重新标定过程噪声参数

**本轮实施范围（统一口径）**：
- 仅修改 `src/rm_auto_aim/gimbal_pipeline` 包
- 不修改旧的 `src/rm_auto_aim/max_entropy_tracker`
- 不修改 `rm_bringup/config/<robot>/gimbal_pipeline.yaml`

**涉及文件**：
- [gimbal_pipeline/src/max_entropy_tracker/filters/dual_radius_spin_ukf.cpp](../../../gimbal_pipeline/src/max_entropy_tracker/filters/dual_radius_spin_ukf.cpp)
- [gimbal_pipeline/config/gimbal_pipeline.yaml](../../../gimbal_pipeline/config/gimbal_pipeline.yaml)

**具体步骤**：

1. 提高平移加速度噪声：
   ```yaml
   # 当前: singer_sigma: 0.5  → 目标加速度 std 仅 0.5 m/s²
   # 建议: singer_sigma: 2.0  → 目标加速度 std 约 2.0 m/s²
   # 高速目标: singer_sigma: 5.0
   ```

2. 修正旋转调参对象：
   ```yaml
   # 当前主链路 4 板 UKF 使用 RotationModel::CV
   # 因此优先调: spin.spin_process_noise_delta_rate
   # 而不是先调: spin.spin_process_noise_delta_acc
   ```

3. 针对不同兵种设计参数组（参考方案中 "v1=100, v2=400" 的量级概念）：
   - `leg`：`singer_sigma` 适度上调，`delta_rate` 小幅上调
   - `hero`：优先提高 `singer_sigma`，再评估 `delta_rate`
   - `infantry_4_1`：先审计是否已过激，不建议继续机械调大

**验证方法**：实弹/模拟测试中对比不同参数下跟踪滞后和轨迹平滑度
4. 验收门槛（建议）：
   - 连续丢跟率不高于基线 +3%
   - 大机动时角度峰值误差较基线下降
   - 控制指令无明显高频抖动新增

## P3: IUKF 迭代更新

**目标**：在 UKF 更新中加入可选迭代，改善大机动/初始化时线性化精度

**涉及文件**：
- [gimbal_pipeline/include/max_entropy_tracker/core/config.hpp](../../../gimbal_pipeline/include/max_entropy_tracker/core/config.hpp)
- [gimbal_pipeline/src/max_entropy_tracker/filters/dual_radius_spin_ukf.cpp](../../../gimbal_pipeline/src/max_entropy_tracker/filters/dual_radius_spin_ukf.cpp)

**具体步骤**：

1. 在 `UKFParameters` 中新增：
   - `iukf_max_iterations` (默认 2)
   - `iukf_convergence_threshold` (默认 0.01)

2. 在 UKF 单观测更新函数中：
   - 用 for 循环包裹现有更新逻辑
   - 每次迭代在更新后的状态重新生成 sigma 点
   - 检查创新量变化是否收敛

3. 触发策略：
   - 跟踪初始化帧：3 次迭代
   - 机动检测触发时：3 次迭代
   - 正常帧：1 次（等同于当前行为）

**验证方法**：
- 对比开关 IUKF 时初始化后的收敛速度
- 确认迭代次数分布合理（大部分帧 1 次即可收敛）

## P4: IMU Slerp 时间插值

**目标**：用 Slerp 插值替代纯 MessageFilter 时间对齐，解决相机-IMU 异步问题

**涉及文件**：
- [armor_detector/src/armor_detector_node.cpp](../../../armor_detector/src/armor_detector_node.cpp) — 图像回调中获取 IMU 姿态处
- [max_entropy_tracker/](../../../max_entropy_tracker/) 中的 tf_handler

**具体步骤**：

1. 维护 IMU 姿态时间戳队列（环形缓冲，约 100ms 窗口）
2. 在图像回调中，用图像时间戳在 IMU 队列中查找相邻两帧
3. 对两个四元数做 Slerp 插值：`q_image = q0.slerp(t, q1)`
4. 用插值后的姿态计算 camera2world 变换
5. 保留 tf2 MessageFilter 作为回退（当 IMU 队列数据不足时）

**验证方法**：
- 对比插值前后的坐标变换结果
- 在相机和 IMU 帧率不同的配置下测试

---

## P5: 通讯延迟动态测量

**目标**：从静态 `timestamp_offset_` 升级到动态延迟估计

**涉及文件**：
- [rm_serial_driver/](../../../rm_serial_driver/) — 串口收发逻辑

**具体步骤**：

1. 上位机在指令包中打发送时间戳
2. 下位机回传时携带收到指令的时间戳（或回传同一时间戳用于 RTT 计算）
3. 上位机收到回传后计算 RTT/2 作为通讯延迟估计
4. 维护延迟的滑动窗口统计（均值、方差）
5. 将动态延迟输入预测模块，替代静态 offset

**验证方法**：
- 统计延迟分布（均值、P99、抖动）
- 对比静态和动态延迟下跟踪精度

## 实施顺序建议

```
P0 (YPD R矩阵) ──→ P1 (启用门控) ──→ P2 (Q参数标定)
                                          │
                                          ▼
                                    实弹验证稳定
                                          │
                          ┌───────────────┼───────────────┐
                          ▼                               ▼
                    P3 (IUKF迭代)                   P4 (IMU Slerp)
                                                         │
                                                         ▼
                                                   P5 (通讯延迟)
```

P0-P2 为基础改进，建议在一个迭代周期内完成。P3-P5 为进阶改进，根据实际测试中暴露的问题选择性推进。

## 执行前置检查（新增）

1. 确认当前启动链路为 `bringup_pipeline.launch.py`，且 `robot` 配置值明确（默认是 `leg`）。
2. 确认参数文件生效顺序：
   - `gimbal_pipeline/config/gimbal_pipeline.yaml`（包默认）
   - `rm_bringup/config/<robot>/gimbal_pipeline.yaml`（机器人覆盖）
3. 本轮文档与实现范围统一为“仅修改 `src/rm_auto_aim/gimbal_pipeline` 包”；若不同步 `rm_bringup` 覆盖参数，则默认启动链路可能继续覆盖本轮默认值。
4. 所有参数改动都需要在目标 `robot` 配置下回放/实测验证，避免“改了但没生效”的假阳性结论。
